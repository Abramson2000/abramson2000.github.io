# Исправление синхронизации Tingli и Cidian

Исходная версия: GitHub `Abramson2000/abramson2000.github.io`, коммит `f5c410f`.
Версии исправления: Tingli **5.60.0**, Cidian **2.11.0**.

## Что исправлено

- Единственное хранилище обоих приложений: `https://api.crmuro.ru`, существующая D1 `tingli-kv`. Старые API не участвуют в синхронизации данных.
- Вместо двух независимых механизмов Tingli используется одна очередь: прогресс, галочки, ДЗ, расписание, оплаты и словарь.
- Отправленные изменения считаются сохранёнными только после подтверждения записи. При сбое они остаются на устройстве, повторяются с задержкой и переживают перезапуск.
- Сервер проверяет исходное значение ключа атомарным SQL-запросом. При конфликте клиент получает актуальное значение, объединяет изменения и повторяет запрос.
- Слияние сравнивает локальное состояние с последней подтверждённой копией. Поэтому намеренное снятие галочки, очищенный ответ и удалённое избранное больше не возвращаются при объединении.
- Ответы на ДЗ обновляются на другом устройстве даже при уже существующем локальном ключе. Фоновое обновление работает при возвращении, восстановлении связи и раз в 30 секунд.
- Совпадающие слова объединяются по содержимому на клиенте и сервере; случайные `uid` не создают дубли. Редактирование текста/раздела оставляет отметку удаления старой записи.
- Cidian больше не заменяет всю локальную копию облачной при запуске/обновлении. Сняты старые блокировки отправки.
- Изменение словаря во время открытой карточки сохраняет объект записи и её локальный ID: обработчики формы продолжают редактировать выбранное слово.
- Слова, явно отправленные из Tingli в Cidian, проходят через сохраняемую очередь `tingli-cidian-outbox-v2`; общий DELETE очереди устранён.
- Новый протокол запрашивает до 20 ключей за раз и не загружает Cidian/страховочные архивы для восстановления Tingli.
- Офлайн-кэши приложений изолированы. Подключённый модуль синхронизации входит в кэш обоих приложений.
- Совместимые чтения `/api/backup` и диагностический `/api/_report` сохранены. Старые административные команды миграции удалены из новой версии Worker.

API v2: `GET /api/sync?list=1`, `GET /api/sync?keys=...`, `POST /api/sync` с `{key,base,value}`. Ответ 409 содержит текущую запись. Схема существующей таблицы `kv` сохраняется.

## Проверка

```bash
python3 tests/sync/check-syntax.py
node --test tests/sync/sync.test.cjs
node tests/sync/app-smoke.cjs
```

Пройдено: 17 тестов с Worker и настоящей SQLite — обрыв POST, перезапуск, ввод во время отправки, два устройства, создание одного ключа одновременно, снятие отметок, очистка ответа, оплаты, удаления, слова с различными uid, ошибочные ответы сервера. Дополнительно исходные скрипты обоих приложений запускаются в Node с заменами DOM; проверяется полученная разметка и редактирование открытой записи.

Это не проверка в настоящем Safari и не проверка опубликованной версии. Действующий API из текущей рабочей среды отвечает HTTP 403; доступов для GitHub push и Cloudflare deploy в переданном архиве нет. Сайты автоматически не обновлены.

## Установка

Распаковать пакет исправлений и запустить `bash deploy.sh` на Mac с авторизованными GitHub CLI и Wrangler. Скрипт применяет патч к свежим исходникам, проверяет код, сохраняет облачный бэкап, сначала публикует API и проверяет протокол, затем создаёт и объединяет PR сайта. Данные базы не пересоздаются и не мигрируются. DNS `crmuro.ru` не меняется.

Нужны `git`, `gh`, `node` (22.13+ либо 24+), `npx`, `python3`, `curl`; GitHub-доступ к указанному репозиторию и Cloudflare-доступ к Worker/D1/routes. Секреты не входят в пакет и не печатаются скриптом. При конфликте с более свежими правками установка прекращается; заменять новые файлы старым снимком нельзя.

## Существенные ограничения

- При первом запуске новой версии у прежних текстовых ответов нет достоверного времени изменения. Различающиеся локальный/облачный ответы сохраняются в локальный журнал `tingli-conflicts-v2`; для первоначального объединения используется локальный непустой текст. После первого подтверждения дальнейшие изменения отслеживаются относительно сохранённой копии. Это нельзя считать восстановлением ранее уничтоженных ответов.
- При одновременном изменении одного и того же поля последняя успешно отправленная правка побеждает; независимые поля объединяются. Для конфликтующих текстовых ответов сохраняются обе версии в журнале.
- Старые клиенты используют прежний протокол; полноценная работа снятия отметок требует обновления приложения на обоих устройствах.
- Аудиозаписи устного ДЗ остаются в IndexedDB устройства, как в исходной программе. Данный ремонт касается синхронизируемых текстовых данных и отметок; перенос самих аудиофайлов между устройствами не добавлен.
- Учебные материалы, логотипы, аудиофайлы и содержание урока 8.3 не изменены.
